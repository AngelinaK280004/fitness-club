# Требования и пользовательские сценарии

## 1. Профили пользователей (User Personas)
На основе анализа предметной области выделены два типа пользователей:

| Характеристика | Клиент (Пользователь) | Оператор (Администратор) |
|---|---|---|
| **Уровень владения ПК** | Низкий | Средний/Высокий |
| **Цель** | Найти расписание, записаться/отменить тренировку | Управлять расписанием, консультировать клиентов |
| **Среда** | Мобильный телефон / ПК | Стандартный ПК с гарнитурой |
| **Требования** | Простой интерфейс, минимум ввода текста, кнопка быстрого вызова | Удобный просмотр расписания, доступ к контактам клиентов |

## 2. Функциональные требования (MoSCoW)

| ID | Требование | Приоритет |
|---|---|---|
| **FR-01** | Система должна отображать расписание тренировок на месяц вперёд. | Must |
| **FR-02** | Система должна предоставлять детальную информацию о тренировке (место, тренер, свободные места). | Must |
| **FR-03** | Система должна позволять инициировать звонок оператору со страницы тренировки для записи. | Must |
| **FR-04** | Система должна позволять инициировать звонок оператору для отмены записи. | Must |
| **FR-05** | Система должна отображать список тренеров и их краткие профили. | Should |
| **FR-06** | Личный кабинет: просмотр личных данных, статистики (посещено/пропущено/осталось). | Must |
| **FR-07** | Система должна отображать уведомления о статусе записей. | Should |
| **FR-08** | Экран «О приложении» с контактами техподдержки и лицензиями. | Could |

## 3. Пользовательские сценарии (Use Cases)

### UC-01: Запись на тренировку
- **Актёры:** Клиент, Оператор.
- **Предусловие:** Клиент авторизован, открыл расписание.
- **Основной поток:**
  1. Клиент выбирает интересующую тренировку.
  2. Система отображает детали (время, место, тренер, свободные места).
  3. Клиент нажимает кнопку «Позвонить».
  4. Система инициирует вызов оператора.
  5. Оператор консультирует и вносит запись в систему.
- **Постусловие:** Клиент записан, ему отправлено уведомление.

### UC-02: Отмена записи
- **Актёры:** Клиент, Оператор.
- **Основной поток:**
  1. Клиент переходит в раздел «Мои тренировки».
  2. Нажимает «Отменить» рядом с нужной тренировкой.
  3. Система инициирует вызов оператора.
  4. Оператор отменяет запись.
- **Постусловие:** Место в расписании освобождено, клиенту отправлено уведомление.

### UC-03: Запись клиента с медицинскими ограничениями
- **Актёры:** Клиент, Оператор, Тренер.
- **Основной поток:** 
  1. Клиент звонит оператору и сообщает об ограничениях по здоровью.
  2. Оператор связывается с тренером для уточнения условий.
  3. Оператор перезванивает клиенту, объясняет адаптированную программу и требования (например, справка от врача).
  4. Клиент подтверждает запись.
